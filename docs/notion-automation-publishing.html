자동 발행·관리 최종 가이드

Notion 데이터베이스에서 각 게시글을 페이지로 작성하고 Published를 체크하면, Cloudflare Worker가 GitHub Actions를 실행해 Hugo 사이트를 다시 빌드하고 GitHub Pages에 배포합니다. 이 문서는 최초 설정부터 글 작성, 수정, 발행 취소, 점검과 장애 대응까지 한곳에 정리한 최종 운영 안내서입니다.

2026년 6월 20일 검증 상태: 자동 발행 코드 배포 준비 완료

동기화 스크립트와 repository_dispatch 워크플로가 기본 브랜치 main에 있으며, Worker 상태 확인 주소도 정상 응답합니다. 실제 자동 발행 여부는 Notion 자동화 활성화, GitHub Actions Secret, Worker Secret이 서로 올바르게 연결되어 있어야 최종 확정됩니다.

원본 관리

게시글의 단일 원본은 Notion입니다. 생성된 Markdown은 직접 수정하지 않습니다.

  1. Notion에서 게시글 페이지를 작성하고 Published를 체크합니다.
  2. Notion 데이터베이스 자동화가 Worker의 webhook 주소를 호출합니다.
  3. Worker가 비밀 헤더를 확인하고 GitHub에 발행은 notion-publish, 발행 취소는 notion-unpublish 이벤트를 보냅니다.
  4. GitHub Actions가 Notion API로 현재 공개된 게시글 전체를 조회합니다.
  5. 본문과 이미지를 Hugo 콘텐츠로 변환하고 사이트를 빌드해 GitHub Pages에 배포합니다.
단방향 동기화입니다.

운영 기준 원본은 Notion입니다. Notion의 글이 GitHub Actions 빌드 과정에서 Hugo 콘텐츠로 변환되지만, GitHub에서 수정한 게시글이 Notion으로 역동기화되지는 않습니다. Notion에서 생성된 글은 항상 Notion에서 수정하세요.

배포할 때 공개 글 전체를 다시 동기화합니다.

webhook은 특정 글 하나를 GitHub로 보내는 장치가 아니라 전체 동기화를 시작하는 신호입니다. Actions가 실행되면 Published가 체크된 페이지를 다시 조회하고, 체크가 해제된 기존 생성 글은 빌드 대상에서 제거합니다.

2. Notion 데이터베이스 속성

데이터베이스의 한 행은 하나의 게시글 페이지입니다. 테이블 속성에는 관리 정보만 입력하고, 실제 게시글 내용은 해당 행을 열어 나타나는 Notion 페이지 본문에 작성합니다.

속성명 Notion 타입 필수 여부 프로젝트에서의 역할
Title 제목 필수 게시글 제목으로 표시됩니다.
Published 체크박스 필수 체크된 페이지만 공개 게시글로 동기화합니다.
Date 날짜 필수 게시 날짜와 게시글 정렬 기준으로 사용합니다.
Section 선택 필수 권장 study, projects, reviews 중 게시 위치를 결정합니다.
Tags 다중 선택 선택 목록 카드와 게시글 상세 화면의 태그 칩, 태그별 모음 페이지에 사용합니다.
Slug 텍스트 선택 게시글 URL을 직접 지정합니다. 비우면 제목으로 자동 생성합니다.
Description 텍스트 선택 화면에는 표시하지 않고 검색엔진용 설명으로 사용합니다. 비우면 본문 앞부분을 자동 요약합니다.

이 블로그는 큰 분류에 Section, 세부 주제에 Tags를 사용합니다. 별도의 Categories 속성은 필요하지 않습니다.

입력 예시

Title       React 렌더링 최적화 정리
Published   ✓
Date        2026-06-19
Section     study
Tags        React, JavaScript, 성능
Slug        react-rendering-optimization
Description React 렌더링 원리와 불필요한 렌더링을 줄이는 방법을 정리합니다.

위 게시글은 다음 주소로 배포됩니다.

https://yoongang02.github.io/study/react-rendering-optimization/

3. 최초 설정 및 보안 값

평소 글을 작성할 때 반복할 작업은 아닙니다. 한 번만 완료하면 됩니다.

  • Notion Internal connection Blog Publisher 생성
  • 원본 게시글 데이터베이스에 Blog Publisher 연결 권한 부여
  • GitHub Actions Secret NOTION_API_KEY 등록
  • GitHub Actions Secret NOTION_DATA_SOURCE_ID 등록
  • Cloudflare Worker 배포 및 Worker Secret 등록
  • Notion 데이터베이스 속성 생성
  • Notion 데이터베이스 자동화 생성 및 활성화
  • 자동 발행 코드와 워크플로를 GitHub 기본 브랜치 main에 반영

서비스별 저장 위치

설정 값 저장 위치 용도
NOTION_API_KEY GitHub Actions Repository secret Actions가 Notion 페이지와 본문을 읽습니다.
NOTION_DATA_SOURCE_ID GitHub Actions Repository secret 동기화할 Notion 데이터 원본을 지정합니다.
NOTION_WEBHOOK_SECRET Cloudflare Worker secret 외부의 무단 webhook 호출을 차단합니다.
GITHUB_TOKEN Cloudflare Worker secret Worker가 저장소에 notion-publish 이벤트를 보냅니다.
X-Webhook-Secret Notion 자동화의 요청 Header 값은 Worker의 NOTION_WEBHOOK_SECRET과 같아야 합니다.

Notion API 키와 GitHub token은 필요한 범위만 허용하고, 노출이 의심되면 즉시 폐기 후 재발급합니다. 실제 비밀 값은 이 HTML이나 Git 저장소에 기록하지 않습니다.

Notion 자동화 설정

  1. 게시글 데이터베이스 상단의 번개 아이콘 또는 Automations를 엽니다.
  2. 새 자동화를 만듭니다.
  3. Trigger를 Published가 checked로 변경될 때로 설정합니다.
  4. Action에서 Send webhook을 선택합니다.
  5. Method는 POST를 사용합니다.
  6. URL에 아래 Worker 주소를 입력합니다.
  7. Custom header에 X-Webhook-Secret과 별도로 발급한 비밀 값을 입력합니다.
  8. 자동화를 저장하고 활성화합니다.
https://yoongang-blog-community.yoongang02.workers.dev/webhooks/notion

워크스페이스 요금제나 권한에 따라 데이터베이스 자동화와 webhook action 사용 가능 범위가 다를 수 있습니다. 메뉴가 보이지 않으면 Notion 워크스페이스 관리자 권한과 현재 요금제를 먼저 확인하세요.

비밀 값은 문서나 게시글에 기록하지 마세요.

NOTION_API_KEY, GITHUB_TOKEN, X-Webhook-Secret 값은 GitHub Secret, Cloudflare Worker Secret, Notion 자동화의 비밀 헤더에만 보관합니다.

발행 취소 자동화

체크 해제만으로 사이트에서도 즉시 글을 내리려면 두 번째 자동화를 만듭니다. Trigger는 Published가 unchecked로 변경될 때로 설정하고, webhook URL은 발행용 URL 뒤에 /unpublish를 붙입니다. 

https://yoongang-blog-community.yoongang02.workers.dev/webhooks/notion/unpublish
  • Method: POST
  • Header: X-Webhook-Secret
  • Header value: 발행 자동화와 동일한 비밀 값

이 요청은 notion-unpublish 이벤트로 Actions를 실행합니다. 동기화 스크립트가 현재 Published 상태를 다시 조회하고, 체크가 해제된 Notion 생성 글과 이미지 폴더를 빌드 콘텐츠에서 제거한 뒤 사이트를 재배포합니다.

4. 평소 게시글 발행 방법

  1. Notion 게시글 데이터베이스에서 New page를 누릅니다.
  2. Title, Date, Section을 입력합니다.
  3. 필요하면 Tags, Slug, Description을 입력합니다.
  4. 페이지 본문에 제목, 문단, 이미지, 코드 등을 사용해 글을 작성합니다.
  5. 미리 작성한 내용을 확인하고 마지막에 Published를 체크합니다.
  6. GitHub Actions가 완료될 때까지 기다린 뒤 실제 사이트를 확인합니다.
Published는 마지막에 체크하세요.

체크되는 순간 배포가 시작됩니다. 이미 체크된 글을 수정하기만 해서는 현재 자동화가 실행되지 않으므로, 수정 배포 방법은 다음 절을 참고하세요.

발행 직전 확인

  • 제목, 날짜, Section이 입력되어 있음
  • Slug가 영구 URL로 사용하기 적절함
  • 본문의 이미지, 링크, 코드 블록이 정상임
  • Description이 검색 결과 설명으로 자연스러움
  • 공개하면 안 되는 개인정보나 비밀 값이 없음

5. 게시글 수정 및 발행 취소

이미 발행된 글 수정

Notion에서 본문을 수정한 뒤 다음 중 하나를 사용합니다.

  1. 권장: Published를 해제하고 다시 체크합니다. 체크 시 발행 자동화가 다시 실행되며 최신 본문으로 사이트를 재배포합니다.
  2. GitHub 저장소의 Actions → Deploy Hugo site to Pages → Run workflow를 실행합니다. 이 방식도 공개된 Notion 게시글 전체를 다시 읽습니다.

게시글 발행 취소

  1. Notion에서 해당 글의 Published 체크를 해제합니다.
  2. 발행 취소 자동화가 /webhooks/notion/unpublish를 호출하면 자동으로 재배포됩니다.
  3. 취소 자동화가 없다면 GitHub Actions에서 워크플로를 수동 실행합니다.
  4. 다음 빌드에서 해당 글이 제외되어 사이트에서 사라집니다.

URL 변경 주의

발행 후 Section이나 Slug를 변경하면 게시글 URL도 변경됩니다. 기존 링크가 깨질 수 있으므로 특별한 이유가 없다면 발행 후에는 유지하세요.

예약 발행

현재 워크플로는 Date가 미래인지 검사해 예약 공개하지 않습니다. Published가 체크되어 있으면 미래 날짜라도 다음 동기화에서 생성될 수 있으므로, 예약 발행이 필요할 때는 원하는 시각까지 체크하지 않거나 별도의 예약 자동화를 구성해야 합니다.

6. Notion 본문 변환 방식

현재 동기화 스크립트는 다음 Notion 블록을 Hugo용 Markdown으로 변환합니다.

  • 일반 문단과 제목
  • 글머리 목록과 번호 목록
  • 체크박스
  • 인용문과 콜아웃
  • 코드 블록과 수식
  • 구분선
  • 이미지와 첨부 파일
  • 북마크와 임베드 링크
  • 표와 중첩 블록

본문 이미지는 빌드할 때 내려받아 게시글의 notion-assets 폴더에 배치합니다. Notion 페이지 커버가 있으면 게시글 대표 이미지로 변환합니다.

변환 결과가 Notion 화면과 완전히 같지는 않을 수 있습니다.

복잡한 컬럼 배치, 일부 임베드, Notion 전용 상호작용은 Markdown 표현으로 단순화됩니다. 새 블록 형식을 처음 사용할 때는 테스트 글로 실제 배포 결과를 확인하세요.

7. 배포 확인 방법

  1. GitHub 저장소의 Actions를 엽니다.
  2. Deploy Hugo site to Pages 실행이 생성되었는지 확인합니다.
  3. 노란색은 실행 중, 초록색은 성공, 빨간색은 실패를 의미합니다.
  4. 성공 후 실제 블로그에서 해당 Section과 게시글 URL을 확인합니다.

워크플로 이름은 Deploy Hugo site to Pages이며, 실행 원인은 repository_dispatch로 표시됩니다. 수동 점검이 필요하면 Run workflow를 실행해 동일한 전체 동기화와 배포를 수행할 수 있습니다.

Notion 자동화부터 GitHub Pages 반영까지는 즉시 완료되는 작업이 아니라 Worker 호출, Actions 빌드와 Pages 배포 시간이 필요합니다.

8. 문제 해결

Published를 체크했는데 Actions 실행이 생기지 않음

  • Notion 자동화가 저장 및 활성화되어 있는지 확인합니다.
  • Trigger가 Published checked인지 확인합니다.
  • Worker URL 끝에 /webhooks/notion이 포함되어 있는지 확인합니다.
  • X-Webhook-Secret 이름과 값이 정확한지 확인합니다.
  • 자동 발행 워크플로가 기본 브랜치 main에 있는지 확인합니다.

Published를 해제했는데 글이 계속 표시됨

  • 체크 해제 자동화의 URL이 /webhooks/notion/unpublish로 끝나는지 확인합니다.
  • Actions에 notion-unpublish 원인의 새 실행이 생성됐는지 확인합니다.
  • 실행 로그에 Removed unpublished page가 표시되는지 확인합니다.
  • Actions가 성공했다면 브라우저 캐시를 새로고침하고 실제 게시글 URL을 다시 확인합니다.

Actions는 실행됐지만 Notion API 오류가 발생함

  • GitHub Secret의 NOTION_API_KEY가 올바른지 확인합니다.
  • NOTION_DATA_SOURCE_ID가 원본 데이터베이스의 Data source ID인지 확인합니다.
  • 원본 데이터베이스에 Blog Publisher connection이 연결되어 있는지 확인합니다.
  • 속성명이 Title, Published, Date, Section과 정확히 일치하는지 확인합니다.

Actions에서 동기화는 성공했지만 Build가 실패함

  • 실패한 실행의 Build 로그에서 첫 번째 오류 위치를 확인합니다.
  • Notion 코드 블록이나 표에 Hugo가 해석할 수 없는 문법이 포함됐는지 확인합니다.
  • 이미지 또는 첨부 파일 URL이 만료되기 전에 Actions가 내려받을 수 있었는지 확인합니다.
  • 문제가 되는 글의 Published를 잠시 해제하고 다시 배포해 범위를 좁힙니다.

게시글이 잘못된 메뉴에 나타남

Section 값을 다음 중 하나로 입력했는지 확인합니다.

study
projects
reviews

본문 수정이 사이트에 반영되지 않음

현재 자동화는 Published가 체크되는 변화를 기준으로 실행됩니다. 본문만 수정했다면 Published를 해제했다가 다시 체크하거나 GitHub Actions를 수동 실행하세요.

Worker 상태 확인

아래 주소가 {"ok":true}를 반환하면 Worker가 실행 중입니다.

9. 운영 체크리스트

글을 발행할 때마다

  • Notion에서 최종 미리보기와 공개 정보 확인
  • Published 체크
  • GitHub Actions 실행 생성 및 성공 확인
  • 실제 URL에서 본문, 이미지, 태그, 모바일 화면 확인

정기적으로

  • Notion integration과 GitHub token의 권한·만료 상태 확인
  • 실패한 Actions 실행과 Worker 오류 로그 확인
  • 깨진 이미지·링크와 오래된 게시글 정보 점검
  • 새 Notion 블록을 도입하기 전 변환 결과 테스트

10. 운영 원칙 요약

  • 게시글의 원본은 항상 Notion입니다.
  • 본문은 데이터베이스 셀이 아니라 각 게시글 페이지 안에 작성합니다.
  • 초안 작성 중에는 Published를 체크하지 않습니다.
  • 발행 시 Published를 체크하고 Actions 성공 여부를 확인합니다.
  • 발행 후 Slug와 Section은 가급적 변경하지 않습니다.
  • Categories는 사용하지 않고 Section과 Tags만 사용합니다.
  • API 키와 webhook 비밀 값은 절대 문서나 저장소에 직접 기록하지 않습니다.

공식 참고 자료

  • Notion 데이터베이스와 페이지
  • Notion 데이터베이스 자동화
  • Notion Webhook action
  • Notion Data source 조회 API
  • GitHub Actions 트리거
