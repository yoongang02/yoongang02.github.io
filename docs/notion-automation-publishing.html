Notion 자동화를 이용한 게시글 발행

Notion 데이터베이스에서 Published 속성을 켜면 즉시 GitHub Actions를 실행하고, 기존 동기화 스크립트가 본문과 이미지를 Hugo 콘텐츠로 변환해 GitHub Pages에 배포하는 구성입니다.

결론: 구현 가능합니다. 예약 실행은 필요하지 않습니다. 다만 GitHub 토큰 보호와 요청 형식 변환을 위해 작은 중계 API를 두는 방식이 가장 안전합니다.

권장 구조

Notion 자동화
Cloudflare Worker
GitHub Actions
GitHub Pages

Notion의 webhook action은 POST 요청과 custom header를 지원하지만, 전송 본문은 선택한 데이터베이스 속성을 기반으로 만들어집니다. GitHub repository dispatch는 별도의 event_type JSON 형식을 요구하므로 Worker가 요청을 검증하고 형식을 변환합니다.

현재 프로젝트에서 유지되는 부분

  • scripts/sync-notion.mjs: 게시글 UI와 독립적으로 동작하며 최신 Notion API 2026-03-11을 사용합니다.
  • NOTION_API_KEY, NOTION_DATA_SOURCE_ID: GitHub Actions secret에 유지합니다.
  • repository_dispatch: notion-publish: Notion 자동화가 시작할 배포 이벤트입니다.
  • 게시글 UI 변경은 Hugo 렌더링 단계에 적용되므로 Notion 변환 로직에 추가 수정이 필요하지 않습니다.

1. GitHub 토큰 준비

  1. GitHub에서 fine-grained personal access token을 만듭니다.
  2. 대상 저장소를 yoongang02/yoongang02.github.io로 제한합니다.
  3. Repository permission의 Contents: Read and write만 허용합니다.
  4. 토큰은 Notion이 아니라 Cloudflare Worker secret에 저장합니다.

2. Cloudflare Worker 생성

다음 Worker는 Notion의 비밀 헤더를 검사한 뒤 GitHub에 notion-publish 이벤트를 보냅니다.

export default {
  async fetch(request, env) {
    if (request.method !== "POST") {
      return new Response("Method Not Allowed", { status: 405 });
    }

    const secret = request.headers.get("X-Webhook-Secret");
    if (!secret || secret !== env.WEBHOOK_SECRET) {
      return new Response("Unauthorized", { status: 401 });
    }

    const notionPayload = await request.json().catch(() => ({}));
    const response = await fetch(
      "https://api.github.com/repos/yoongang02/yoongang02.github.io/dispatches",
      {
        method: "POST",
        headers: {
          "Accept": "application/vnd.github+json",
          "Authorization": `Bearer ${env.GITHUB_TOKEN}`,
          "X-GitHub-Api-Version": "2026-03-10",
          "User-Agent": "notion-blog-publisher"
        },
        body: JSON.stringify({
          event_type: "notion-publish",
          client_payload: {
            source: "notion-automation",
            received_at: new Date().toISOString(),
            notion: notionPayload
          }
        })
      }
    );

    if (!response.ok) {
      return new Response("GitHub dispatch failed", { status: 502 });
    }

    return new Response("Accepted", { status: 202 });
  }
};

Worker 설정의 secret에는 다음 값을 등록합니다.

이름값
GITHUB_TOKEN앞에서 만든 fine-grained GitHub token
WEBHOOK_SECRET충분히 긴 임의 문자열

3. Notion 데이터베이스 자동화 설정

  1. 게시글 데이터베이스 상단의 ⚡ Automations를 엽니다.
  2. Trigger를 Published 속성이 checked로 변경될 때로 지정합니다.
  3. Action에서 Send webhook을 선택합니다.
  4. URL에 배포된 Worker 주소를 입력합니다.
  5. Custom header에 X-Webhook-Secret과 Worker의 WEBHOOK_SECRET 값을 입력합니다.
  6. 전송 속성에는 Title, Slug, Published 정도만 선택합니다. 실제 본문은 GitHub Actions가 Notion API로 다시 읽습니다.
Notion webhook action은 유료 플랜에서 사용할 수 있습니다. 무료 플랜이라면 Notion integration webhook이나 Make/Zapier 같은 중계 서비스가 대안입니다.

4. 발행 동작

  1. Notion에서 글을 작성합니다.
  2. Published를 체크합니다.
  3. Notion 자동화가 Worker를 호출합니다.
  4. Worker가 GitHub의 repository_dispatch 이벤트를 생성합니다.
  5. GitHub Actions가 공개된 전체 Notion 글을 다시 동기화하고 Hugo를 빌드합니다.

주의사항

  • Notion 본문은 webhook payload에 포함되지 않습니다. 현재 스크립트가 API로 본문을 다시 조회하는 것이 정상 동작입니다.
  • GitHub token을 Notion custom header에 직접 넣지 않는 편이 안전합니다.
  • Published를 연속으로 여러 번 바꾸면 빌드가 반복될 수 있습니다. GitHub Actions의 concurrency 설정이 이전 실행을 정리하도록 구성할 수 있습니다.
  • 발행 취소도 즉시 반영하려면 Published가 unchecked로 변경될 때 동일한 webhook을 호출하는 두 번째 자동화를 추가합니다.
